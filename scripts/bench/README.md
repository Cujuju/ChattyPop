# Archive writer benchmark

Run `benchArchiveWrites.mjs` with the absolute public repository's `plugins` directory. It uses installed dependencies and disposable databases. It never starts or stops the app or opens its archive. `WRITE_BENCH_HOST` optionally selects an absolute baseline host checkout; unset it to measure the current checkout.

The mixed fixture inserts 20,000 messages, 8,000 attachments and 3,200 link shares over 390 days. Attachments, Links and Analytics install their real rollups. Timed writes use a native archive connection, as Core does, without the plugin database facade. Three runs compare no rollup triggers, each trigger family alone, and all triggers. Metadata triggers have no timed entity writes in this fixture; their samples are a noise control. Span triggers run against an empty run history, so this fixture measures their fixed per-message cost rather than overlap searches against existing runs.

The re-fetch fixture ingests 1,000 messages with preview text, then re-ingests unchanged payloads in one writer transaction. It records count-statement preparations, executions and their separate elapsed time. Callbacks are no-ops, isolating archive ingestion from downstream rule work.

Each timed writer operation is synchronous and uninterrupted on Core. Its duration is therefore its blocking turn. The summary reports median ingest time and the longest observed blocking turn. This deliberately exposes large caller batches; it does not imply a scheduling yield inside an atomic write. Shared dirty-mark expansion runs later, with a yield after each bounded batch.

JSON lines retain every sample, process CPU time and SQLite `total_changes()` deltas, including trigger writes. Compare runs on the same machine without overlapping test suites. Disk cache, other processes and fixture setup can affect absolute wall time. Preparation/execution counts, row-change counts and coalesced dirty-mark contracts provide deterministic verification alongside timings.

## Recorded result: 2026-10-19

`archiveWriteResults.json` retains the source commits and every native-writer sample. Bulk median: **4,308.49 → 3,799.63 ms**; process CPU: **4,282 → 3,781 ms**. The no-trigger controls were 2,264.89 / 2,993.15 ms wall and 2,234 / 2,703 ms CPU. Incremental all-trigger CPU above those controls fell from 2,048 to 1,078 ms. Partition invalidation alone fell from 1,001 to 220 ms above its CPU control, and from 105,920 to 858 additional SQLite row changes.

The longest all-trigger turn was **4,395.08 → 4,804.14 ms**. This noisy run does not establish a longest-turn improvement; large atomic batches still block Core for their full duration. Baseline family CPU deltas were approximately partition 1,001 ms, reference 875 ms, span 313 ms; metadata had no timed entity writes. These deltas are attribution samples, not additive estimates; external machine load was not controlled.

Unchanged re-fetch median: **2,021.43 → 1,919.17 ms**; CPU **2,172 → 1,796 ms**. Count preparations fell **2,000 → 1**, with 2,000 executions retained. Median preparation time fell **431.96 → 0.42 ms**; execution time was **78.77 → 61.37 ms**. The longest re-fetch turn was **2,433.14 → 2,501.83 ms**, also not improved in this run. The separate notification contract verifies that 1,000 trigger-covered changes issue zero writer queries.

## Bounded ingestion: 2026-10-19

Set `WRITE_BENCH_ENTRY=bench/ingestTurns.ts` and run the same launcher for the real writer fixture. `WRITE_BENCH_HOST` selects the baseline checkout. The runner copies a disposable plugin-created schema, disposes its plugin schedulers, then seeds 400,000 messages and 390 stored span days. Timed writes use `Archive`: 100-message live pages, unchanged re-fetches, and 20,000-message backfills with attachments and repeated preview links. Three samples retain SQL execution timings and a timer heartbeat; this conservatively includes commit and scheduling time between yields. SQL instrumentation adds overhead. Other machine load was not controlled. No real profile or running app is used.

`ingestTurnResults.json` retains every sample. Backfill median elapsed **44,185.64 → 22,321.28 ms**; longest uninterrupted segment **62,261.42 → 570.47 ms**. New live-page median elapsed **640.19 → 140.84 ms**; longest segment **788.23 → 107.73 ms**. Unchanged-page median elapsed **382.90 → 31.22 ms**; longest segment **428.41 → 8.76 ms**. The measured variant groups shared-link notifications by partition. Subsequent guards cover reference-row relocation and account switches; a final scheduling change also yields after the last slice so repeated tiny imports cannot starve I/O. These retain every measured commit boundary.

Production fetch/import paths commit at most 16 rows before `setImmediate`, reducing the next slice toward a 50 ms target after slow work. This is a cooperative bound: one message, a filesystem stall, or GC cannot be preempted. Cursor commits proceed from the fetched edge; only the last older slice can set completion. Each slice includes derived rows and durable marks before notifications. A restart replays any unfinished edge. Importers await `ingestMessagesBatched` outside metadata transactions; failures retain completed slices.

The original native fixture deliberately retains its single atomic transaction to isolate trigger costs; its longest turn is not the production batching result. Its final all-trigger median was **7,184.34 ms**, with a **5,006.11 ms** no-trigger control, versus the previous **3,799.63 / 2,993.15 ms**. Absolute throughput improvement is not established by that noisy comparison. Incremental CPU above the control was **938 ms**, previously **1,078 ms**. Reference queue changes fell **41,280 → 468**; span changes **20,000 → 781**. Reference/span CPU deltas were **16 / -156 ms** relative to the control, within substantial run noise; a negative delta is not negative work. Reference classification coalesces days with a drain epoch; span overlap searches use read helpers and generation-checked, bounded application. Pending channel gates remain durable until expansion completes.

Final integration used host `582fa96b` (main `4e20d259`) and plugins `c70f8617` (main `0d8ad2d`), including the landed Analytics definitions and read-index changes. Backfill median was **22,413.53 ms**, longest segment **878.60 ms**; new-page median **141.85 ms**, longest **68.61 ms**; unchanged-page median **50.08 ms**, longest **26.01 ms**. No sampled segment reached one second. These final samples are retained separately as `integratedAfter`; the earlier samples remain for comparison. The final plugin base differs from the baseline, so this integrated result does not isolate ingestion changes alone.

Running-app catch-up still needs independent measurement. `core-call-stall` accumulates synchronous time across async slices, so its cumulative number alone is not a longest-turn measurement. Large DCE file reading, JSON parsing and validation still occur before the yielding message writer and are outside this fixture.
